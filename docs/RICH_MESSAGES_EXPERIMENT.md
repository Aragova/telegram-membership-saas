# Rich Messages — безопасный первый эксперимент ViMi Pay

> **Исторический пилот PR #87–#89.** Актуальный глобальный контракт:
> [RICH_MESSAGES_PLATFORM.md](RICH_MESSAGES_PLATFORM.md).
> Новая реализация включается по умолчанию на всей платформе; старые
> `TMS_RICH_FILE_CHECKOUT_BOT_IDS` больше не управляют глобальным режимом.


## Область изменений

Только **экран выбора оплаты цифрового файла** и **предпросмотр владельца**.
Визуальный слой использует официальный метод Telegram Bot API
`sendRichMessage` (Bot API 10.1+) и Rich HTML:
заголовок, компактная таблица цены и количества вложений, сворачиваемое
описание и обычная клавиатура.

**Никаких изменений** платёжных методов, ставок, заявок, подписок,
выдачи файлов, финансовой истории, RLS, аудита, миграций и callback_data.
Сами администраторские реквизиты/инструкции не переводятся и не меняются.

## Проверка до включения покупателям

1. После мержа и **только на staging** пересобрать `customer-supervisor`
   с `compose.yaml` и `compose.light100.yaml`. Миграций нет.
2. В подключённом боте с аккаунта владельца:
   `Продажа файлов → Папки и товары → Товар → ✨ Rich-предпросмотр`.
3. Предпросмотр вызывает настоящий Bot API `sendRichMessage`, но не
   создаёт счёт, не показывает покупателю покупку, не вызывает оплату.
   Кнопка «Карточка товара» возвращает к прежнему экрану.
4. Если библиотека или Bot API не поддерживает Rich Messages, отображается
   старая HTML-карточка и отдельное сообщение о fallback.
5. Протестировать переключение RU/EN и отображение на телефоне и десктопе.

## Выборочное включение

**По умолчанию выключено для всех ботов.**

Чтобы включить **только для выбранного подключённого бота**, нужно задать
в окружении запуска customer-supervisor:

```bash
TMS_RICH_FILE_CHECKOUT_BOT_IDS=123456789
```

Можно несколько числовых ID, через запятую. Это **Telegram bot ID**, а не
ID пользователя или канала. В `compose.yaml` переменная пробрасывается
только в customer-supervisor и customer-bot, а в `Settings` строка
по умолчанию пустая. Ни `app`, ни центральный бот не затронуты.

На разрешённом боте только экран выбора **способа оплаты файла** будет
использовать Rich Messages; штатные кнопки с исходными `fm:` и `fs:`
callback_data остаются без изменений. Неудачный `sendRichMessage`
из-за неподдерживаемого API или форматирования приводит к обычному
`sendMessage`. Не ретраим сетевые тайм-ауты, чтобы не дублировать сообщения.

**Быстрый визуальный откат:** удалить `TMS_RICH_FILE_CHECKOUT_BOT_IDS`
и пересоздать только `customer-supervisor` с тем же overlay.
Никаких изменений PostgreSQL не требуется. Если PR понадобится
откатить целиком — revert merge commit после согласования.

## Приёмка

- Предпросмотр работает только из панели владельца.
- RU/EN корректны, пользовательский текст экранируется.
- Оригинальная клавиатура и callbacks сохранены.
- По умолчанию все покупатели видят прежний интерфейс.
- При выборочном включении меняется только визуальная карточка.
- Создание ручного платежа, Stars, чек, подтверждение и выдача
  продолжают использовать существующий код.
