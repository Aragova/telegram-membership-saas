# ViMi Pay — продажа файлов (отдельный функциональный блок)

## Сценарий владельца

В **своём подключённом боте** откройте админ-панель
→ **📂 Продажа файлов → ⚙️ Управление продажами**.

1. Создать папку (до 100).
2. В папке создать товар: название и стоимость в целых Telegram Stars.
3. В черновике при необходимости исправить название, цену, добавить описание.
4. Прислать до 20 файлов сообщениями (документ, фото, видео, аудио, GIF).
5. Нажать «Готово», просмотреть содержимое карточки и **Опубликовать**.
6. При необходимости архивировать товар или вновь вернуть в продажу.
   Ранее купленные файлы остаются доступны покупателям.

Файлы не скачиваются на сервер SaaS. Сохраняются только Telegram
`file_id` привязанного бота. Получателю передаётся файл Telegram
только после подтверждения оплаты. Нельзя подменить файл после
публикации; уже оформленная продажа сохраняет исходную цену и название.

## Сценарий покупателя

В подключённом боте: каталог подписок → «📂 Купить файлы» или
`/files` → папка → товар → **⭐ Купить**.

Сервер создаёт отдельный `FilePurchase` со снимком цены.
Telegram получает `sendInvoice(currency="XTR", provider_token="")`.
`pre_checkout_query` повторно сверяет Telegram ID, конкретный
bot ID, project_id, заказ, цену, публикацию и состояние блокировки.
До `successful_payment` Telegram **ни один файл не отдаётся**.
После подтверждённого `telegram_payment_charge_id` покупка
фиксируется однократно, покупателю посылается набор файлов.

`/myfiles` и кнопка «Мои файлы» открывают постраничную историю
оплаченных товаров (8 на страницу). Каждый товар, в том числе снятый
с продажи, можно скачать повторно. Для потерянного подтверждения
есть отдельная кнопка «🔄 Проверить оплату Stars»: она сверяет
незавершённый заказ с транзакциями самого Telegram, проверяет
`source.user.id`, `invoice_payload`, сумму Stars и charge ID,
после чего фиксирует действительно оплаченный заказ. Это помогает
восстановить покупку, если база была недоступна в момент уведомления.
Проверка использует до 20 страниц по 100 транзакций; при слишком
большом журнале или недоступности Telegram используется /support.
Выдача и повторная доставка разрешены только исходному
Telegram покупателю в исходном боте; другие пользователи не могут
получить файл, подменив callback ID.

## Финансы и ограничения

- Telegram требует **Stars XTR** для цифровых товаров внутри ботов.
  Старые ручные платежи **за подписки** не изменяем.
  См. [официальные правила](https://core.telegram.org/bots/payments-stars).
- Нет выдуманного автоматического курса RUB/USD/EUR/UAH/BYN ↔ Stars.
  Сумма в XTR задаётся владельцем явно; Stars принадлежат конкретному
  боту по правилам Telegram.
- Отдельная таблица `file_sale_purchases`: нельзя считать
  цифровую продажу подпиской, продлевать канал, выдавать Entitlement
  или смешивать GMV валют ручных платежей с XTR.
- Повторный callback `successful_payment` с тем же charge ID
  идемпотентен; чужой charge ID не подтверждает старый заказ.
  Оплаченный заказ и сумма защищены DB-триггером от изменения/удаления.
- Файлы и записи каждого проекта защищены PostgreSQL FORCE RLS.
  Товар всегда привязан к конкретному `telegram_bot_id`. Пользователь
  не может открыть медиаданные без **своей оплаченной покупки**.
- Сервис ограничен по количеству папок, товаров, файлов и черновых
  заказов во избежание неконтролируемого роста данных.
- Telegram delivery — внешняя операция. Если отсылка не завершилась
  **после успешной записи** платежа, подтверждённый заказ остаётся в
  базе и покупатель может получить файлы через `/myfiles`.
  Если сбой произошёл **до записи** платежа после списания Stars,
  `/myfiles → Проверить оплату Stars` сверяет Telegram ledger, не
  выдавая файлы по скриншоту/слову покупателя.
  Если восстановить автоматически не удалось, используется `/support`.
- Для тестов денег используйте Bot API Telegram test environment,
  а не реальные платежи подписчиков.

## Тестирование после разрешённого мержа

1. Staging: обновить **только customer-supervisor** после применения
   миграции `0037_digital_file_sales`; центральный бот не меняется.
2. В тестовом подключённом боте создать папку/товар с 2 вложениями,
   изменить цену черновика, опубликовать.
3. Проверить на покупательском аккаунте, что до оплаты вложения
   не отдаются, а чужое получение по ID не работает.
4. Пройти тестовый Telegram Stars invoice → pre-checkout → успешная
   оплата → авто-выдача → /myfiles. Повторное уведомление не должно
   повторно начислить продажу.
5. Архивировать товар, убедиться, что старый покупатель может
   его скачивать; другой покупатель его не видит.
6. Убедиться, что подписки, обычные заявки и финансовая история
   действующих каналов не изменились.

## Не входит в этот PR

Перевод XTR в рубли и другие валюты без согласованного курса,
автоматический вывод Stars/TON, объединение финансов подписок и файлов,
внешние платёжные методы для цифровых товаров и загрузка приватных
файлов через сторонний хостинг.


## Динамическое стартовое меню (после PR #81)

В подключённом боте покупатель видит два разных варианта `/start` и
`/menu`, без ручного переключателя:

- Если нет ни одной активной папки с опубликованным товаром **в этом боте**,
  показывается прежнее меню подписок, без кнопки «Купить файлы».
- Если хотя бы один файл-товар опубликован, первой кнопкой показывается
  название активного канала/группы проекта. Она открывает неизменённый
  каталог тарифов и прежнюю цепочку оплаты подписки.
- Ниже следуют только активные папки с опубликованными товарами, строго
  с названиями, введёнными владельцем. Кнопки открывают товары соответствующей
  папки; покупки и выдача защищены прежними проверками оплаты и доступа.
- Последняя кнопка — «🌐 Language / Язык». Смена языка перерисовывает
  соответствующее актуальному состоянию меню.
- На этом стартовом экране нет кнопок истории подписок и поддержки;
  команды и сервисные обработчики не удаляются.
- В админ-панели «Рассылки / Продажа файлов» и «Смотреть гостем /
  Настройки» расположены в двух соседних рядах по две кнопки.
  Используются только Telegram-native стили; обработчики не изменяются.

Статус публикации файла и наличие активной папки определяют показ меню
динамически, а не по устаревшему пользовательскому кешу.


## Ручные оплаты файлов и дополнение Stars (миграция 0038)

Администратор может назначать отдельную цену в RUB/USD/EUR/UAH/BYN
и других валютах, поддерживаемых **уже подключёнными активными методами
оплаты его бота**. При создании файла первая цена выбирается по валюте,
затем можно добавить остальные цены через карточку товара
→ «💱 Цены в валютах». Star-цена необязательна для новых товаров;
старые опубликованные товары сохраняют свою исходную цену Stars.
Реального обменного курса Stars ↔ fiat система не предполагает.

После выбора опубликованного файла покупатель сразу попадает на экран
«Оформление покупки файла»: название, цена, выбор валюты и методов,
такой же, как в подписках. Первым отображается ручная оплата, а
Stars — отдельной опцией только если назначена цена в XTR.

При выборе ручного метода:

1. Фиксируется самостоятельный заказ файла со **снимком** цены,
   валюты, имени товара, метода и инструкции (без создания PaymentRequest,
   Subscription, Payment или Entitlement подписки).
2. Покупатель получает реквизиты и «Я оплатил»; обязателен ответ на
   специальное сообщение бота фотографией чека или PDF/JPG/PNG/WEBP.
3. Заявка попадает владельцу / платёжному менеджеру, в журнале остаётся
   запись чека. Владелец может открыть список «🧾 Проверка оплаты файлов».
4. Подтверждение / отклонение выполняется только уполномоченным
   администратором после самостоятельной проверки перевода.
   Повторное подтверждение идемпотентно.
5. Только подтверждённый заказ открывает передачу файлов и /myfiles.
   История Stars и ручных покупок отображается совместно, а финансовые
   записи и разные валюты не смешиваются.

Защита: project/bot/user scope, FORCE RLS, отдельная таблица
file_sale_manual_orders и immutable DB trigger для суммы, решения
и полученного чека; старые записи не меняются при изменении цен.
Для staging необходима миграция 0038 и пересборка только
customer-supervisor с compose.light100.yaml.

**Предупреждение:** Telegram требует Stars для цифровых товаров,
продаваемых *внутри* бота; оплата таких товаров вручную может
противоречить правилам платформы. Администратор должен учитывать
этот риск. Сервис не выдаёт файлы до подтверждения оплаты.
