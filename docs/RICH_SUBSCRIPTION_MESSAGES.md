# ViMi Pay — Rich Messages для тарифов подписки (пилот)

## Что меняется

При выборе **конкретного тарифа** клиент может видеть Rich-карточку с таблицей:

- 📢 Канал / Channel — название подключённого канала;
- 🎟 Тариф / Plan — только если администратор ввёл собственное название;
- 🗓️ Срок / Duration — локализованный период;
- 💰 Цена / Price — действительная цена с исходной валютой.

Если тариф называется просто «1 месяц» или «навсегда», лишняя строка
с повтором названия не появляется. Пользовательские названия сохраняются
как есть; HTML-символы экранируются. Внизу исходная клавиатура валют
и активных способов оплаты, с теми же `buy:`, `offer:`, `cat:` callback.

**Не меняются** каталог, создание счетов, подтверждение чеков,
финансовая история, доступ в канал, PostgreSQL, Telegram Stars,
оплата файлов и базовые меню.

## Безопасный предпросмотр владельца

В подключённом боте:
`👀 Смотреть гостем → выбрать тариф → ✨ Rich-предпросмотр`.

Предпросмотр подлинный: `sendRichMessage`, данные реальных тарифов.
Кнопки используют только `own:pv*` и не запускают платёж.
Право владельца перепроверяется перед предпросмотром.
Если Rich не поддерживается, показывается прежний текстовый экран.

## Выборочное включение для покупателей

По умолчанию **отключено для всех ботов**.
Отдельная настройка (не путать с файлами):

```env
TMS_RICH_SUBSCRIPTION_CHECKOUT_BOT_IDS=8528484991
```

Это числовой Telegram ID бота. Можно перечислить несколько через запятую.
Настройка пробрасывается в `customer-supervisor` и `customer-bot`.
Покупатели остальных ботов продолжают получать старый экран.

Сначала проверить предпросмотр на staging, затем явно включить только
`@onlyyoufullbot` и проверить RU/EN, валюты, выбор способа оплаты.

**Особенность Telegram:** Rich отправляется новым сообщением, тогда как
старый экран редактировался. Каталог/список тарифов сохраняется в чате
как предыдущий экран; кнопка возврата на Rich-карточке по-прежнему ведёт
в действующий каталог.

## Обновление staging без миграций

После проверенного PR и явного разрешения на мерж достаточно пересобрать
`customer-supervisor` с `compose.yaml + compose.light100.yaml`.

При развёртывании тестового бота сохранить **обе** переменные, если уже
используется Rich для файлов:

```env
TMS_RICH_FILE_CHECKOUT_BOT_IDS=8528484991
TMS_RICH_SUBSCRIPTION_CHECKOUT_BOT_IDS=8528484991
```

Быстрый откат Rich подписок: убрать только
`TMS_RICH_SUBSCRIPTION_CHECKOUT_BOT_IDS` и пересоздать
`customer-supervisor`. Классический интерфейс вернётся без
миграций и потери заказов. При ошибке в формате Rich код сам
переходит к классическому экрану; транспортные сбои не ретраятся,
чтобы избежать двойных сообщений.
